# Speaking Viewer (SV) 4.0 — C++

Перенос программы SV («говорящий просмотрщик» текстов для незрячих; автор —
Владимир Довыденков, при содействии С. Г. Саприна, П. Сысолятина и
С. Картавцева, как сказано в её справке) с Free Pascal на C++. Исходник на
Паскале лежит в `reference/pascal` байт в байт и служит образцом:
интерфейс, клавиши, звуки и **все сообщения программы перенесены без
изменений** (проверяется `tools/check_messages.py`, см. ниже).

Что добавилось к исходнику:

* сборка для **Windows x86 и x64** (llvm-mingw или Visual Studio) и для
  **Linux x86 и x64** (gcc или clang);
* **UTF-8** — и внутри программы, и снаружи: тексты, имена файлов, консоль,
  настройки; однобайтовые кодировки (DOS-866, Windows-1251, KOI8-R)
  остались только там, где их диктует внешний мир;
* справка — не `SV.HLP`, а обычный текст `SV_help.txt` (UTF-8) рядом с
  программой, те же 45 разделов;
* темп речи на клавишах — как в справке (разделы 1 и 12): **Ctrl+[
  замедляет, Ctrl+] ускоряет**.

## Сборка на Windows

Требуется CMake 3.25+ (`winget install Kitware.CMake`) и один из тулчейнов:

* **llvm-mingw** (по умолчанию) — `winget install MartinStorsjo.LLVM-MinGW.UCRT`;
* **Visual Studio 2022+** с нагрузкой «Разработка классических приложений на C++».

```
build_x86.bat [-b mingw|msvs] [keep]
build_x64.bat [-b mingw|msvs] [keep]
build_all.bat [-b mingw|msvs] [keep]
```

Батник находит инструменты, зовёт `cmake -P cmake/build.cmake` и всегда
заканчивается `pause`. Результат — в `build\x86\` или `build\x64\`: программа,
`SV_help.txt`, настройки `SV.INI`, `SV.CFG`, `SV.DCL` (уже лежащие настройки
пользователя не затираются) и помощники архивов и fb2 (см. ниже). `keep`
оставляет дерево сборки `obj\`.

То же из командной строки:

```
cmake -P cmake/build.cmake x86|x64|all [-b mingw|msvs] [keep]
cmake -P cmake/build.cmake check [x86|x64|all] [-b ...]     собрать и проверить
cmake -P cmake/build.cmake clean
```

Номер сборки (`build/BUILD_NUMBER.txt`, версия 4.0.0.N) растёт на единицу за
каждый запуск сборки; x86 и x64, собранные вместе, получают один номер.

## Сборка на Linux: deb-пакет

Нужны CMake 3.25+, gcc/g++ (или clang), make и dpkg-dev (для x86 — ещё
`gcc-multilib g++-multilib`). Одной командой на Debian/Ubuntu (от root):

```
apt install cmake build-essential dpkg-dev
```

Сборка и установка — одной командой:

```
./build.sh install
```

Скрипт соберёт пакет и поставит его через `apt`, спросив пароль: sudo —
если пользователь в группе sudo, иначе root (через `su`). Остальные
варианты:

```
./build.sh [x64|x86|all|check|install|clean] [keep]
```

Результат — пакет `build/sv_4.0.0.N_amd64.deb` (`i386` для x86; номер
сборки растёт, старый пакет той же разрядности удаляется) и та же
программа без установки в `build/linux-x64/`. Поставить готовый пакет
вручную:

```
su -
apt install /полный/путь/sv_reborn/build/sv_*_amd64.deb
```

* Именно `su -` (с дефисом) или `sudo`: у `su` без дефиса остаётся PATH
  пользователя без `/usr/sbin`, и dpkg прерывает установку с
  предупреждениями `start-stop-daemon`/`ldconfig not found in PATH`.
* Именно `apt` (не `dpkg -i`) и путь к файлу со слешем (`./…` или полный):
  так apt понимает, что это файл, и сам доставит всё из зависимостей
  пакета. Их список вычисляет при сборке `dpkg-shlibdeps` по самой
  программе (libc, libstdc++), к ним добавлена ALSA (звук); рекомендуемые
  — `p7zip-full` или `7zip`, `unzip`, `xsltproc` (архивы и fb2) — apt
  ставит вместе с пакетом.
* Сообщение apt `Download is performed unsandboxed as root…` при установке
  из домашней папки безвредно (служебный пользователь `_apt` не видит
  закрытую папку); `./build.sh install` ставит из временной папки, и его
  нет.
* Удалить: `apt remove sv` (от root). Папка `~/.config/sv` остаётся.

### После установки

```
sv [/r] [файл...]      запуск; sv --help — ключи, man sv — подробно
```

| Где | Что |
|---|---|
| `/usr/bin/sv` | команда запуска |
| `/usr/lib/sv/SV` | сама программа |
| `/usr/share/sv/` | справка, настройки по умолчанию, `SV.DCL`, помощники `sv_arc.sh`, `sv_fb2.sh`, `fb2/` |
| **`~/.config/sv/`** | **папка программы для пользователя** |

`~/.config/sv/` (или `$XDG_CONFIG_HOME/sv`, или любая папка из переменной
`SV_HOME`) — то, что на Windows было бы папкой рядом с `SV.exe`: здесь
`SV.INI`, `SV.CFG`, `SV.DCL`, закладки `SV.VBM`, история `SV.LDD`, позиции
`SV.LPS`; сюда же кладутся свои помощники для `SV.DCL` (в нём эта папка —
`$SV`), файл замен `SV.CHF`, таблицы перекодировки. При первом запуске
настройки копируются сюда из `/usr/share/sv`, а справка и помощники ставятся
ссылками на файлы пакета — их обновляет новая версия. Чтобы переделать
помощник под себя, замените ссылку своим файлом: пакет его не тронет.
Удаление пакета эту папку не удаляет.

Звук выводится через miniaudio: библиотека выбирает доступный системный
аудиосервер (PulseAudio, PipeWire) или ALSA. При отсутствии устройства
программа работает молча.

Пресеты для IDE: `mingw-x86`, `mingw-x64`, `msvs-x86`, `msvs-x64`,
`linux-x64`, `linux-x86` (`cmake --preset …`, `cmake --build --preset …`).

## Архивы и fb2

Файл, расширение которого есть в `SV.DCL`, программа отдаёт указанной там
команде, а из распакованного предлагает выбрать файл (единственный
открывается сразу). В `SV.DCL` `$SV` — папка программы: помощники лежат
рядом с `SV.exe`.

* **Windows.** `zip`, `rar`, `7z`, `arj`, `lzh`, `cab`, `tar`, `gz` —
  `sv_arc.cmd`: распаковывает 7-Zip из `archivers\` (он же открывает rar),
  заодно вложенные архивы с fb2 или txt, превращает fb2 в текст
  (`fb2\fb2_to_txt.exe`) и собирает всё читаемое в один список. Отдельная
  книга `.fb2` — `sv_fb2.cmd`. 7-Zip лежит в репозитории, конвертер fb2 —
  нет (см. ниже).
* **Linux.** То же делают `sv_arc.sh` и `sv_fb2.sh` (в установленной
  программе — ссылки в `~/.config/sv`); распаковщик —
  системный: `7z` (p7zip), а без него `bsdtar`, `unzip`, `unrar` или `tar`;
  fb2 превращается в текст `xsltproc` (пакет `xsltproc`, иначе книга
  открывается как есть).

Файлы пакета берутся из `runtime/`, для своей ОС — ещё из
`runtime/windows` или `runtime/linux`.

**Конвертер fb2 для Windows** (`fb2_to_txt.exe` и его библиотеки
`iconv.dll`, `libexslt.dll`, `libxml2.dll`, `libxslt.dll`, `zlib1.dll`) в
репозиторий не входит — его лицензия неизвестна; он есть только в
готовых пакетах релиза. Чтобы собрать пакет с ним, положите эти файлы в
`runtime/windows/fb2/` (папка в `.gitignore`), сборка перенесёт их в
пакет. Без них всё работает, только книги fb2 в архивах открываются как
есть, без превращения в текст.

## Устройство

```
src/text/      UTF-8, Unicode (регистр), однобайтовые кодировки, строки,
               поиск слов, пользовательские замены (SV.CHF)
src/platform/  всё, что зависит от ОС: консоль (Windows и POSIX раздельно),
               пути, запуск программ, печать, звук (miniaudio)
src/sound/     звуковые сигналы и «музыка» автора (@частота:длительность)
src/speech/    речь: нормализатор текста (SPICK), числительные (SAYFORM),
               речевое ядро newfon (принимает KOI8-R)
src/ui/        экран 80x25, клавиатура, диалоги (DIALOG.PAS), справка
src/convert/   текст из Word 97 и HTML
src/sv/        сама программа: окно текста (viewer), закладки, главный цикл
               (app), команды (commands), меню и настройки (menu, settings),
               файлы записей SV.CFG, SV.LDD, SV.VBM, SV.LPS (records),
               main.cpp — главная программа SV.PAS
vendor/        подмодули: newfon_core — речевое ядро (C), miniaudio — звук;
               собираются статически
runtime/       то, что кладётся рядом с программой; windows/ и linux/ --
               SV.DCL и помощники архивов и fb2 для своей ОС
reference/     исходник на Паскале (авторский), образец для сверки
tests/         проверки (cmake -P cmake/build.cmake check)
tools/         check_messages.py, con_drive (прогон программы по сценарию)
packaging/deb/ запуск sv, man-страница и copyright для deb-пакета
               (собирает cmake/deb.cmake)
```

Программа написана на обычном C++17 со стандартной библиотекой: строки —
`std::string` в UTF-8, работа по символам — `std::u32string`, файлы —
`std::filesystem` и потоки. Эмуляции Паскаля (`string[N]`, файлы Турбо
Паскаля, модули Dos/Crt, самописная «память» на куче и диске) больше нет.

### Текст и кодировки

* Внутри программы весь текст — UTF-8. Строка текста раскодируется при
  чтении из файла по выбранному режиму («Обычная» — DOS-866, Windows, KOI8-R,
  UTF-8, пользовательская таблица); длины и позиции в строке — в символах.
* Файл не читается в память целиком: при загрузке строится оглавление строк,
  строка читается по требованию. Предела длины текста нет.
* Однобайтовые кодировки остались на границах: тексты в этих кодировках,
  поля DBF (866), речевое ядро (KOI8-R), печать на Windows (866), чтение
  старых файлов настроек. В DOS-866 программы места F2..F9 заняты
  украинскими Є є Ї ї І і Ґ ґ.
* Файлы записей (`SV.CFG`, `SV.LDD`, `SV.VBM`, `SV.LPS`) сохранили
  паскалевскую раскладку и размеры: файлы прежних версий читаются, а эти —
  ими. Строки в них пишутся в UTF-8, короткие поля (имя закладки, время
  будильника) — в 866, если строка в неё укладывается.
* `SV.INI`, сохранённые тексты и блоки — UTF-8; старый `SV.INI` в
  Windows-1251, `SV.CHF` и `SV.DCL` в 866 читаются.
* Пути — UTF-8 с родным разделителем ОС (`\` у Windows, `/` у Linux).

## Проверки

* `cmake -P cmake/build.cmake check` — собрать и прогнать `tests/`
  (строки, кодировки, UTF-8, регистр, замены, слова, определение кодировки,
  пути с Unicode, файлы записей).
* `python tools/check_messages.py` — все строковые литералы Паскаля с
  русскими буквами (вне комментариев) должны найтись среди литералов C++
  байт в байт. Сейчас: 965 литералов, 0 недостающих. Исключения перечислены
  в самом скрипте: четыре литерала, которых не было и в собранной программе
  (`{$ifdef debug}` и т. п.), и литералы кода автора, который никогда не
  выполнялся (с причиной для каждой группы).
* `tools/con_drive.cpp` (Windows) — запускает SV в своей консоли, подаёт
  нажатия клавиш из сценария и снимает экран. Сборка с `-DSV_SPEECH_TRACE=ON`
  не говорит, а пишет всё сказанное в файл из переменной окружения
  `SV_SPEECH_LOG`: так речь и экраны прогонялись по одинаковым сценариям
  против прежней сборки (см. `docs/AUDIT.md`).

## Отличия от исходника

Сделаны сознательно; всё остальное повторяет исходник, включая его
странности. Подробности и то, как это проверялось, — в `docs/AUDIT.md`.

* **Темп речи.** У автора `Set_SpSpeed_Slower` уменьшала Temp (речь быстрее),
  и клавиши Ctrl+[ и Ctrl+] работали наоборот справке. Здесь процедуры названы
  по действию и привязаны по справке: Ctrl+[ — медленнее, Ctrl+] — быстрее
  (шкала прежняя: 0 — быстрее всего, 150 — медленнее всего).
* **Украинские буквы** произносятся по их значению. У автора таблица речи
  писалась под другую кодовую страницу (CP1125), и Є читалось как «г»,
  Ґ — как «йи», Ї — как «е».
* **Любые символы.** Текст в UTF-8 показывается, ищется и сохраняется без
  потерь; латинские буквы с диакритикой читаются как базовые, незнакомые
  символы при чтении молчат, при движении по символам (и по Del) называется
  их номер. Фраза длиннее 255 символов больше не обрезается.
* **Определение кодировки.** Строка с не-ASCII, правильная как UTF-8, —
  UTF-8 (у исходника русский текст в UTF-8 определялся как KOI8 или
  Windows: байт D1 в KOI8 — гласная «я»). Кроме того, исходник проверял не
  саму строку, а кусок следующей.
* **Word 97 и HTML** преобразуются в UTF-8: сохраняются типографские знаки
  (тире, кавычки, ё), `&#число;` даёт любой символ, заголовок страницы в
  UTF-8 центрируется и строки переносятся по символам, а не по байтам.
* **Статистика** (Ctrl+S) считает верно: у исходника выходила лишняя строка
  (чтение за концом буфера), ширина строки в UTF-8 считалась в байтах, а у
  строк с CR LF — на единицу меньше.
* **База данных** открывается на первой записи (у исходника — на нулевой:
  на экран шёл заголовок файла); год последней правки — две цифры
  («24/07/02», у исходника «24/07/10»).
* **Разделитель разрядов** на экране — всегда точка (у исходника до первой
  сказанной программой цифры — запятая, потом точка).
* **Настройки.** Разделы `SV.INI` читаются в любом порядке. Раздел справки
  F1 в диалоге «Загрузка» — 34-й (у автора не назначался).
* **Списки прошлых вводов** (`SV.LDD`) не стираются: у исходника первый
  ввод имени файла при пустом списке пересоздавал файл со всеми списками.
  Значения не обрезаются.
* **Закладки**: переход на закладку в последней строке текста работает, а
  закладка на пропавший файл даёт сообщение об ошибке.
* **Поиск назад** доходит до первой строки.
* **Сохранение** текста и блока (F2, Ctrl+K Ctrl+W) — в UTF-8; «Создан
  файл» говорится только о новом файле.
* **Справка** — текстовый `SV_help.txt` вместо `SV.HLP`. Загружается сразу
  после настроек: у исходника F1 в диалоге открытия файла при запуске
  обращался к ещё не загруженной справке.
* **Словарь** (Ctrl+F6): у исходника по Esc файл словаря `SV.DIC` стирался —
  он был копией, распакованной из архива, но распаковку автор отключил, и
  стирание уничтожало сам словарь. Здесь словарь не стирается.
* **Последние файлы**: пропавший с диска файл из списка пропускается (у
  исходника программа на нём останавливалась с «Не найден загружаемый файл»).
* **Архивы** (`SV.DCL`): команда не переводится в верхний регистр (на Linux
  имена от регистра зависят); `.cmd`/`.bat` на Windows запускаются через
  `%COMSPEC%` с правильными кавычками; после распаковки программа
  возвращается в каталог, из которого её запустили. Вместо DOS-архиваторов
  и отсутствовавших `worddoc.cmd`/`pdf.cmd` в пакете — рабочие помощники
  (см. «Архивы и fb2»); строка `doc:` из `SV.DCL` убрана: она перехватывала
  встроенное чтение Word 97.
* **Память.** Выбор памяти (верхняя, обычная, диск) остался в настройках и
  в строке состояния, но текст всегда читается из файла: предела длины
  текста и вопроса «Можно загрузить только N% текста» больше нет.
* Не создаётся `SV.SCR` (копия экрана DOS до запуска); мышь не
  поддерживается. Защита от зависаний исходника: `&#` в HTML с ошибкой,
  укорачивание пути в диалоге файлов, «ьо» в нормализаторе речи.
* Сообщения при выходе (`Stop`) печатаются в консоль, из которой программа
  запущена, после закрытия её экрана.

## Linux: клавиатура

Программа работает в любом терминале (xterm, GNOME Terminal, Konsole, kitty и
пр.) и в текстовой консоли. В терминале из-за самого протокола нельзя узнать
нажатие Alt без другой клавиши (быстрый поиск Alt+буква в диалоге файлов
работает, одиночный Alt — нет) и то, что Ctrl нажат в данный момент (обрыв
речи нажатием Ctrl); остальные клавиши Ctrl, Alt и Shift работают, в том
числе Ctrl+[ и Ctrl+] (через modifyOtherKeys у xterm-совместимых и протокол
клавиатуры kitty). В текстовой консоли Linux работает всё.

**F10 и Alt+буква в графических терминалах.** MATE Terminal, GNOME
Terminal и Xfce Terminal по умолчанию забирают F10 (своё меню) и
Alt+буква (пункты своего меню) — до программы эти клавиши не доходят.
В MATE Terminal и GNOME Terminal установленная `sv` делает всё сама: на
время работы выключает этот перехват (`gsettings`), а при выходе
возвращает как было — и когда окно закрыли, и (при следующем запуске),
если программу прервали. Прежние значения хранятся до выхода в
`~/.config/sv/terminal.saved`. Пока SV работает, это действует на все окна
этого терминала.

В Xfce Terminal перехват выключается вручную: «Правка → Параметры →
Дополнительно», «Отключить клавишу вызова меню (F10)».

В текстовой консоли (Ctrl+Alt+F1…F6) и в xterm, kitty, Konsole ничего
настраивать не нужно.
